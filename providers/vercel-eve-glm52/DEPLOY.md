# One-click Vercel deployment for OpenMinis GLM-5.2

The bridge is isolated under `providers/vercel-eve-glm52` and is now merged into the `main` branch.

## 1. Create the dedicated GitHub repository and Vercel project

[Deploy/import `minis-eve-glm52` on Vercel](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fkhs0927%2Fhermes-minis%2Ftree%2Fmain%2Fproviders%2Fvercel-eve-glm52&project-name=minis-eve-glm52&repository-name=minis-eve-glm52-provider)

The source points directly at the stable `main` branch and the `providers/vercel-eve-glm52` subdirectory. The Deploy Button pre-fills `minis-eve-glm52-provider` as the new Git repository name and `minis-eve-glm52` as the Vercel project name.

When Vercel shows the Git clone/create step, approve creation of the new GitHub repository. That produces the dedicated repository requested for Minis instead of requiring the monorepo at runtime.

If your Vercel account chooses to deploy from the existing source rather than create a new Git repository, the runtime still works, but creating the dedicated repository is preferred for long-term maintenance.

## 2. Add only the bridge secret

Create this encrypted Vercel environment variable for Production and Preview:

```text
MINIS_BRIDGE_API_KEY=<a-long-random-secret-known-only-to-your-Minis-client>
```

Keep these defaults unless you intentionally change the billing behavior:

```text
PROMO_END_AT=2026-08-28T00:00:00.000Z
ALLOW_PAID_AFTER_PROMO=false
```

For a Vercel-hosted Eve deployment, the official Eve deployment path can authenticate AI Gateway string-model access using the Vercel project's OIDC identity. Therefore `AI_GATEWAY_API_KEY` is normally not required on Vercel. It remains available for local/self-hosted development when project OIDC is unavailable.

Do not put any Vercel AI Gateway credential into OpenMinis.

## 3. Use the mobile setup page

After deployment, open this URL on the iPhone:

```text
https://YOUR-PROJECT.vercel.app/setup
```

The setup page contains no server secret. Enter the same `MINIS_BRIDGE_API_KEY` saved in Vercel.

The page provides three actions:

1. **Health check** — validates the bridge without calling a model.
2. **Tiny GLM-5.2 test** — makes one short model request.
3. **Download Minis provider JSON** — creates a provider import file locally in the browser. It inserts the correct Vercel deployment origin, `providerType=openAI`, `appendV1Suffix=true`, and the bridge key in the format OpenMinis imports.

Before increasing usage, inspect Vercel AI Gateway Observability/Usage after the tiny model test and confirm that the Eve/GLM-5.2 request is actually billed at **$0** under the promotion. The repository guard stops requests after the configured promotion boundary, but it cannot independently prove billing eligibility.

## 4. Import directly into OpenMinis

Current OpenMinis iOS supports **Or Import Provider from File** in the Add Provider screen. Use the JSON generated by `/setup`:

```text
Minis → Settings → Providers → Add Provider
→ Or Import Provider from File
→ vercel-eve-glm52.minis-provider.json
```

OpenMinis imports the provider type, label, API-key credential, custom base URL, and Append `/v1` setting. If the imported JSON has no embedded model list, OpenMinis refreshes models from the bridge `/v1/models` endpoint, which exposes only `zai/glm-5.2`.

Manual fallback configuration:

```text
Provider: OpenAI
Credential: API Key
Name: Vercel Eve GLM-5.2
Custom Base URL: https://YOUR-PROJECT.vercel.app
Append /v1: ON
API Key: YOUR_MINIS_BRIDGE_API_KEY
Model: zai/glm-5.2
```

Do not choose `Responses API (v3)` for this bridge. The implemented compatibility endpoint is `/v1/chat/completions`.

## 5. Test Minis Skills / MCP

The bridge accepts the OpenAI `tools` array produced by OpenMinis. Tool selection is adapted inside the Eve turn and translated back into standard OpenAI `tool_calls`; OpenMinis remains the executor and permission boundary for Skills/MCP actions.

Start with a read-only tool. Confirm that the model requests a tool, Minis executes it, and the following `role: tool` result is consumed correctly before enabling tools with destructive side effects.

## Stop-spend behavior

The bridge is locked to `zai/glm-5.2` and refuses inference after the configured promotion window when `ALLOW_PAID_AFTER_PROMO=false`. To continue after the promotion, replace the model/routing strategy with a verified free route or explicitly opt into paid usage.
